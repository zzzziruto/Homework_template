# Dance×Dance

두 휴대폰·태블릿이 자동으로 연결되어 DJ와 DANCER를 나누는 댄스 브레이크 앱입니다. 컴퓨터는 관찰 전용이며 참가자로 등록되지 않습니다.

## 기존 흐름

두 번째 모바일이 접속하면 3초 뒤 역할을 무작위로 배정하고, 역할 화면을 2초 동안 표시합니다. 댄서의 움직임 100회를 두 화면에서 함께 셉니다. 완료 화면의 한 번 더·나가기, 센서 권한 요청, 재접속과 호스트 교체 흐름을 유지합니다.

DJ 화면은 사용자가 첨부한 Artboard 2 시안을 기준으로 배치합니다. 중앙에 좌우 HI/MID/LOW 두 줄, 각 데크 바깥쪽 볼륨, 하단 네 개씩의 패드와 CUE/재생 버튼, 원판 중앙 BPM, 중앙 미션 숫자를 유지합니다. BPM은 소수 부분만 작게 표시하고 별도 BPM 글자는 붙이지 않습니다. `assets/dj-layout.svg`에 시안의 배경·구분선·슬라이더 라벨을 두고 실제 조작 요소를 같은 좌표에 배치했습니다. 예전 `dj-original.png`는 보존합니다. 곡명과 BPM 숫자는 현재 음원·템포를 반영하며 시안의 예시 값으로 고정하지 않습니다.

## 오디오 조작

- **Play/Pause:** DJ가 직접 누르면 해당 데크를 재생하거나 일시 정지합니다. 역할 화면이나 서버의 Play 상태만으로 소리를 자동 재생하지 않습니다. 처음 한 번은 기존 MP3와 스크래치 버퍼를 준비하며, 별도의 3초 재생 대기는 없습니다.
- **CUE:** 해당 데크를 처음 위치로 되돌리고 정지합니다. 템포와 EQ는 유지합니다.
- **스크래치:** 터치한 데크만 일시 정지하고 무음으로 앞뒤 위치를 움직입니다. 손을 떼면 이전에 재생 중이었던 경우에만 이어서 재생합니다. 움직이지 않고 탭하면 처음으로 돌아가지 않습니다. 승인된 테스트의 3배 감도와 ±4배 속도 제한을 사용합니다.
- **볼륨:** 데크별 실제 음량을 조절합니다. 0은 즉시 완전 무음입니다.
- **템포:** 0.75~1.25배이며 음높이 유지를 활성화합니다. 재생 전·중 모두 설정할 수 있습니다. 드래그 중 원판 중앙 BPM은 즉시 미리 표시하고, 실제 재생 속도는 손을 놓을 때 한 번 적용합니다. Safari에서 잦은 재생 속도 변경으로 생기는 끊김을 줄이기 위한 동작이며, 같은 속도·음정 보정 값은 반복 적용하지 않습니다. 템포 조절은 재생·정지나 재생 위치를 변경하지 않습니다. BPM은 원래 BPM × 재생 속도를 소수점 둘째 자리로 표시합니다.
- **HI/MID/LOW:** 각 데크 독립, 기본 0 dB, ±12 dB입니다. 노브를 중심 주위로 시계 방향 회전하면 증가하고 반시계 방향이면 감소합니다. 두 번 누르면 0 dB로 돌아갑니다. 노브 아래 숫자 표시는 없습니다. 키보드는 방향키로 조절, Enter로 초기화합니다.

두 데크는 기존 `music/Bad Romance_Lady Gaga_The Fame Monster (International Deluxe).mp3`를 재사용합니다. 승인된 소스와 바이트가 동일한 음원이며 원래 BPM은 119입니다. 하단 패드의 터치·선택 상태 공유는 유지했고 선곡 기능은 확장하지 않았습니다. 다른 MP3 파일은 변경하지 않았습니다. 다른 곡을 연결할 때는 해당 곡의 확인된 BPM 메타데이터를 사용해야 하며 자동 BPM 분석은 포함하지 않았습니다.

소리는 DJ 기기에서 재생합니다. 댄서와 관찰 컴퓨터는 자동으로 음원을 재생하지 않습니다. 미션 완료·나가기·역할/라운드 변경·연결 끊김·페이지 숨김 시 양쪽 데크를 즉시 멈춥니다. 늦게 끝난 재생 준비나 스크래치 응답이 다시 재생하지 않도록 취소합니다. 나가기에서는 오디오 컨텍스트, 버퍼 URL과 준비 중인 요청도 정리합니다.

## 실행

공개 접속 주소는 [Dance×Dance 열기](https://zzzziruto.github.io/Homework_template/DanceTogether/?v=20261129-tempo1)입니다. 예전 `DanceTogether/` 주소도 최신 `Dance×Dance/` 폴더로 자동 연결합니다. 컴퓨터 관찰 화면과 두 모바일 모두 이 공개 주소를 열면 같은 접속 그룹을 사용합니다.

`start.command` 또는 다음 명령으로 정적 서버를 실행합니다. 프로젝트 최상위가 아닌 이 폴더에서 실행하세요.

```sh
python3 -m http.server 8785
```

컴퓨터 미리보기는 `http://localhost:8785`입니다. 실제 휴대폰 센서와 AudioWorklet은 HTTPS에서 확인하세요. GitHub Pages에 배포할 때는 `Dance×Dance/` 폴더 전체와 기존 음원을 함께 포함합니다. 두 모바일은 같은 폴더 URL을 열면 되며 같은 Wi-Fi는 필수가 아닙니다.

`localhost`는 서버를 실행 중인 컴퓨터 안에서만 열리는 미리보기입니다. 서버 터미널을 닫으면 접속되지 않으며, 공개 주소를 연 모바일과 다른 접속 그룹이 됩니다. 컴퓨터에서 모바일 접속 상태를 볼 때도 위 공개 주소를 사용하세요. VS Code의 이 폴더 전용 실행 작업도 정적 미리보기 서버를 사용합니다.

현재 웹 배포 버전은 `20261129-tempo1`입니다. `?` 도움말에서 버전을 확인할 수 있습니다. 화면·스타일·하위 모듈·오디오 워크릿·배경 이미지에 같은 버전 키를 적용해 이전 코드가 섞이지 않게 했습니다. 로컬 수정은 관련 파일을 커밋·푸시하고 GitHub Pages 배포가 성공해야 공개 주소에 반영됩니다. 편집기 설정, 인증서·기록과 사용하지 않는 음원은 배포에 포함하지 않습니다.

통신은 기존 `wss://demoserver.p5party.org`를 사용합니다. EQ 공유 필드를 포함한 연결 버전은 6입니다. 업데이트 후 기존 모바일 탭을 닫고 두 기기에서 새로 열어주세요. `/api`와 예전 `server.py`는 현재 앱에서 사용하지 않습니다. 기존 `data/`와 `.certificates/`는 변경하거나 배포하지 않습니다.

## 구현과 검증

- `app.js`, `index.html`, `style.css`: 기존 화면 이벤트와 오디오 연결.
- `audio/dj-mixer.mjs`: 사용자 제스처, DJ 역할·미션 수명주기와 오디오의 연결.
- `audio/audio-engine.mjs`, `eq.mjs`, `media-position.mjs`, `scratch-worklet.mjs`, `scratch-core.mjs`: 승인된 오디오 엔진과 정리·비동기 취소 보완.
- `audio/deck-settings.mjs`, `knob-rotation.mjs`: 원래 BPM·템포와 원형 EQ 입력 계산.
- `session.mjs`, `party-client.mjs`, `motion.mjs`: 두 기기 역할, 컨트롤 공유와 센서 처리.

이 폴더에서 실행합니다.

```sh
node --test tests/*.test.mjs
```

자동 테스트 58개가 통과합니다. 승인된 소스의 스크래치·EQ·BPM 회귀 테스트와 기존 미션 테스트를 포함하며, 완료/나가기 중 재생 준비·스크래치 종료가 늦게 끝나는 경우, CUE와 비동기 seek 충돌, 양쪽 즉시 정지, EQ 쓰기 권한을 추가 검증했습니다. 템포 회귀 테스트는 양쪽 데크의 연속 입력 중 재생 유지, 손을 놓을 때 한 번만 속도 적용, 반복 갱신 시 속도·음정 보정 재설정 방지, 완료/연결 해제/나가기 후 늦은 템포 적용 취소를 포함합니다. 컴퓨터 Safari에서 실제 음원과 동일 믹서·오디오 엔진으로 두 데크 각각 0.75배·1.25배를 확인했으며, 드래그 중과 적용 후 재생 위치 진행 및 오디오 분석기의 신호 유지를 검증했습니다. 기존 Safari 로컬 화면에서 확인한 이미지·배치, 음원 준비, 데크별 독립 재생도 유지합니다.

실제 p5.party 서버의 격리된 방에서는 독립된 두 참가자 클라이언트와 관찰 클라이언트로 역할 배정, EQ·템포 공유, 100회 미션 완료와 재생 상태 해제, 재시작, 양쪽 나가기까지 통과했습니다. 실제 휴대폰 두 대를 사용한 검증은 아닙니다.

실제 iPhone/iPad의 음질, 터치 감도, 센서와 오디오 권한은 해당 기기에서 최종 확인이 필요합니다. 데스크톱 또는 모의 센서 테스트로 실제 휴대폰 검증을 대신했다고 주장하지 않습니다.
